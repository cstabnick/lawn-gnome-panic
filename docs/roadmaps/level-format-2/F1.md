## Environment
Read `docs/roadmaps/level-format-2/_common.md` (and the file it points to) first. This game has no tests of its own except the golden one: `npm test -w games/gnome-front` runs vitest (the package already has a `test` script).

## Goal
Gnome Front's arena lives in a JSON level document (`src/data/levels/arena.level.json`): the bases, flags and vehicle slots as markers, the ground's mounds and flattening radii, the landmarks at the five flags (their prefab, scale, offset from the flag and collision circles) and the rules for the scattered cover. The game reads them from there. The arena does not change: `arena.golden.test.ts` passes unchanged, which pins every constant, the ground height on a grid, every obstacle (position, size, ORDER) and where `buildWorld()` puts every object (position, rotation, scale, ORDER).

## Change
- `games/gnome-front/src/data/levels/arena.level.json`: one `LevelDoc` (`format 'lawn-level'`, `version 1`, `game 'gnome-front'`, `id 'arena'`, `name 'The Back Garden'`, `bounds { w: 2 * ARENA_HALF, d: 2 * ARENA_HALF }`, `stamps: []`, `paths: []`, `props: []`):
  - `markers` (in this order): the two bases `{ id: 'base-0'|'base-1', kind: 'base', x, z, data: { team, yaw } }`; the five flags `{ id: 'A'..'E', kind: 'flag', x, z, data: { name } }`; the nine vehicle slots `{ id: 'slot-<i>', kind: 'vehicle', x, z, data: { vehicle, team, yaw } }` (i = index in `VEHICLE_SLOTS`). Numbers exactly as today (`yaw: Math.PI` is `3.141592653589793`).
  - `data.mounds`: the seven `FEATURES` of `terrain.ts` `{ x, z, r, h }`, same order. `data.flatten`: `{ edge: { inner: 4, outer: 20 }, base: { inner: 22, outer: 40 }, flag: { inner: 12, outer: 24 } }` (the smoothstep ranges `flatMask` uses for the fence edge, each base and each flag).
  - `data.landmarks`: the landmark placements of `buildLandmarks`, IN THE ORDER the code creates them (A's birdbath, B's four veggie beds in the order the code lists them, C's fountain, D's shed, E's compost heap), each `{ at: '<flag id>', dx, dz, prefab, scale, rotY, obstacles: [ { dx, dz, r, h } ... ] }` where `(dx, dz)` is the offset from the flag `at` and the obstacles' `(dx, dz)` are also offsets from that flag, in the order the code pushes them. (Example: the shed is `at: 'D', dx: -11, dz: 0, prefab: 'garden-shed', scale: 4`, with four obstacles; each veggie bed's `rotY` is `0` or `Math.PI / 2` as in the code.) The prefab's height `y` is still the ground height at its x, z, as in the code.
  - `data.cover`: `{ seed: 1234, tries: 5000, edge: 8, avoid: { flag: 14, base: 26, slot: 6, cover: 8 }, layers: [ ... ] }` with one layer per `scatter()` call in order: `{ prefab, count, scale, sink?, spin?, obstacle: { r, h } }` (round-bush: count 70, scale 2, `sink: 0.25`, obstacle 1.6/2.2; garden-rock: 30, scale 3, `spin: true`, 1.2/1.4; flower-pot: 20, scale 4.5, 0.9/1.3; tree-stump: 15, scale 3.2, 1.1/1.0; cone-pine: 8, scale 5, 1.0/12). `spin: true` means the code calls `rand()` once more per placed object to set `rotation.y = rand() * 2 * Math.PI`; keep that call order EXACTLY (the generator is order-sensitive).
- `games/gnome-front/src/levelDoc.ts` (new): imports the JSON, defines and exports the typed `ArenaData` (`mounds`, `flatten`, `landmarks`, `cover`), `ARENA_DOC`, and pure helpers `docBases(doc)`, `docFlags(doc)`, `docVehicleSlots(doc)`, `docHalf(doc)` returning exactly the shapes `config.ts` exports today. It must not import `config.ts` at run time (type-only imports are fine).
- `games/gnome-front/src/config.ts`: `ARENA_HALF`, `BASES`, `FLAGS`, `VEHICLE_SLOTS` are computed from `ARENA_DOC` with the SAME exported types and values (`FlagDef.id` stays `'A' | 'B' | ...`; `BASES` is the 2-tuple). Nothing else in `config.ts` changes.
- `games/gnome-front/src/terrain.ts`: `FEATURES` and the `flatMask` smoothstep ranges come from `ARENA_DOC.data`. The formulas do not change.
- `games/gnome-front/src/world.ts`: `buildLandmarks` and `buildCover` are driven by `data.landmarks` and `data.cover` (a small generic loop each) and produce exactly the same objects, obstacles and random-number sequence as before. `buildHQs`, `buildFence`, `buildGround`, `buildLights` stay as they are.
- `games/gnome-front/src/levelDoc.test.ts` (new): the document passes `validateLevelDoc`; 5 flags with ids A..E, 2 bases, 9 vehicle slots; `FLAGS`/`BASES`/`VEHICLE_SLOTS` equal what the markers say; `data.cover.layers` counts sum to 143; the document survives `JSON.parse(JSON.stringify(...))` unchanged.
