Read `docs/roadmaps/level-format-2/_common.md` (and the file it points to) first.

## Goal
Click-to-move pathfinding can be told that some ground is cheaper (roads), so paths can prefer a road to cutting across rough ground. It is wired in but **off by default**: with the default setting every path is exactly what it was.

## Read first
- `games/gnomes-of-gnomomia/src/pathfind.ts`: `findPath3(from, goal, step, maxExpand)`, its cost accumulation (`g`), the heuristic (octile distance) and the smoothing pass. `src/pathfind.test.ts` (how walking is simulated).
- `games/gnomes-of-gnomomia/src/player.ts`: `pathTo()` calls `findPath3`. `src/config.ts`: `TUNING` and `WORLD.roadHalfWidth`. `src/terrain.ts`: `distToRoad`.

## Change
- `src/pathfind.ts`: `findPath3` gets a fifth optional parameter `opts?: { cost?: (x: number, z: number) => number; minCost?: number }`. When `cost` is given, a step into cell `(ni, nj)` costs `(diagonal ? SQRT2 : 1) * Math.max(minCost, cost(ni, nj))` instead of `(diagonal ? SQRT2 : 1)`, and the heuristic is multiplied by `minCost` (default `1`; pass the smallest value `cost` can return, so the heuristic stays admissible and paths stay optimal). `cost` defaults to none: with no `opts`, every number and every path is identical to today. The line-of-sight smoothing pass must not cut across more expensive ground than it saves: when `cost` is given, only join two waypoints if the straight line between them is clear AND its average `cost` (sampled every 1 m) is not more than 5% above the average `cost` along the original waypoints between them; otherwise keep the waypoint.
- `src/config.ts`: add `roadPathBias: 1` to `TUNING` with the comment "Cost of walking on a road relative to open ground for click-to-move: 1 = no preference (the default), 0.8 = prefer roads."
- `src/player.ts`: `pathTo()` passes `opts` only when `TUNING.roadPathBias < 1`: `{ cost: roadCost, minCost: TUNING.roadPathBias }` where `roadCost(x, z)` returns `TUNING.roadPathBias` when `distToRoad(x, z) < WORLD.roadHalfWidth` and `1` otherwise, memoised per call by cell (`Map<number, number>` keyed by the rounded cell) so each cell asks `distToRoad` once. Otherwise it calls `findPath3` exactly as now.
- `src/pathfindCost.test.ts` (new): (1) with no `opts`, and with `opts` whose `cost` is always 1, the path equals the path with no `opts` (several start/goal pairs in Mossbottom built with the real `terrain` and `standY`, like `pathfind.test.ts`); (2) on a synthetic world (a custom `step` function over a flat plane where `step` always succeeds) with a cheap strip (`cost` 0.5 on `z in [10, 12]`) and start `(0, 0)`, goal `(40, 20)`, the path has at least one waypoint inside the strip and costs less than the straight path under the same cost function (compute both with a small helper that integrates cost along the waypoints), while with `cost` ignored it is the straight line; (3) with `minCost` 0.5 the result is not worse than the same search with `minCost` 1 under the cost function (admissibility); (4) `TUNING.roadPathBias` is `1`.

## Contract
```ts
export function findPath3(from: Point3, goal: Point3, step: StepFn, maxExpand?: number, opts?: { cost?: (x: number, z: number) => number; minCost?: number }): Point3[];
```
