## Goal
Props authored in a zone's level document (`ZoneDef.props`, world coordinates) are drawn in the game as real prefabs, standing on the ground.

## Read first
- `games/gnomes-of-gnomomia/src/config.ts`: `ZoneDef.props?: readonly PropDef[]` (type from `@lawn/level`: `prefab`, `x`, `z`, `rot?`, `scale?`, `tint?`, `solidR?`). They are already in world coordinates at run time. Colliders for `solidR` are already added by `terrainCore.ts`; you only draw.
- `games/gnomes-of-gnomomia/src/dressing.ts`: how the world's set pieces are built and added (find the function the world calls per zone / at start-up, `buildDressing`, and how objects are parented, `addMesh`, `heightAt`). Follow its patterns.
- `packages/prefabs/README.md` and `packages/prefabs/src/index.ts`: `buildPrefab(id, opts)` (its `opts`: `scale`, `tint`), what it throws for an unknown id.

## Change
- `games/gnomes-of-gnomomia/src/levelProps.ts` (new): `export function buildLevelProps(parent: THREE.Object3D, props: readonly PropDef[], groundAt: (x: number, z: number) => number): THREE.Object3D[]`.
  For each prop: `const g = buildPrefab(p.prefab, { scale: p.scale ?? 1, ...(tint) })`; position `(p.x, groundAt(p.x, p.z), p.z)`; `rotation.y = p.rot ?? 0`; set `castShadow`/`receiveShadow` on its meshes like the rest of dressing does; add to `parent`; collect and return the groups. `p.tint` is a `'#rrggbb'` string: convert to a number only if `buildPrefab`'s option takes a number, otherwise skip tint. An unknown prefab id must not throw: `console.warn` once per id and skip it.
- `games/gnomes-of-gnomomia/src/dressing.ts`: call it for every zone that has `props`, from the place that already builds each zone's dressing (so it is built once, with the same parent and lifetime as the other set pieces), passing `heightAt` from `./terrain`. Nothing else in `dressing.ts` changes.
- `games/gnomes-of-gnomomia/src/levelProps.test.ts` (new): if `buildPrefab` runs under vitest's node environment, test that two props produce two groups at the right x/z with `y` from the `groundAt` you pass and the right `rotation.y`, and that an unknown id yields one fewer group and one warning (spy on `console.warn`). If `buildPrefab` cannot run in node (it needs the DOM), do not fight it: write the test for the unknown-id path only, using `vi.mock('@lawn/prefabs')`, and say so in your answer.
