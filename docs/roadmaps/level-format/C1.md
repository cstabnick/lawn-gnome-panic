## Environment
Read `docs/roadmaps/level-format/_common.md` first and follow it. Other workers are, at the same time, converting the zone files to JSON (`src/levelDocs.ts`, `src/content.ts`, `src/data/zones/*`), so the zone data may change under you between runs; the bake must depend only on the final `ZONES` object, never on how it was written.

## Goal
Walkability is pre-baked. A script bakes it into a small committed JSON file; the game loads it so the static part of `isBlocked` is one lookup; a check fails the game's `build` when the bake is stale.

## Change
- `src/bakeWalk.ts`:
  - `walkTileSpecs(zones)`: for each zone with `!z.indoor`, sorted by `id`: `{ id, rect: { minX: o.x - h, maxX: o.x + h, minZ: o.z - h, maxZ: o.z + h } }` with `o = z.origin ?? {x:0,z:0}` and `h = z.half + WORLD.blend`.
  - `bakeWalkTiles(t, specs, into?)`: for each spec `into.setTile(bakeTile(spec.id, spec.rect, (x, z) => t.staticSolidAt(x, z)))`; returns `into` (a new `WalkGrid` when not given).
  - `computeBakeHash(t, zones)`: returns a 16-hex-digit string. Build ONE string and hash it with FNV-1a over UTF-16 code units, two independent 32-bit lanes (different offset bases, e.g. `0x811c9dc5` and `0x9747b28c`), printed as two zero-padded 8-digit hex numbers. No node APIs (it also runs in the browser). The string is `JSON.stringify` of an object built in this fixed key order: `{ zones, world, water, deltas, fingerprint }` where
    - `zones`: for each outdoor zone sorted by id: `[id, origin x, origin z, half, shrine x, shrine z, regions as [id,x,z,r], lakes as [x,z,r], houses as [x,z,r], decks as [x,z,w,d,y,stair], walls as [x1,z1,x2,z2], exits as [to,x,z], theme flora, floraDensity, hilliness, stamps (as is), paths (as is), props as [x,z,solidR ?? 0]]`;
    - `world`: the `WORLD` object; `water`: `TUNING.waterLevel`;
    - `deltas`: `t.deltas.toJSON()`;
    - `fingerprint`: a string of `'0'`/`'1'` for `t.staticSolidAt` at 8192 points: for `i` in `0..8191` take spec `specs[i % specs.length]` and a point from one `mulberry32(20240607)` stream inside its rect.
- `src/walkBake.ts`:
  - `import bake from './data/levels/walk.bake.json'`.
  - `export const BAKED_WALK_HASH: string = (bake as WalkFile).inputHash;`
  - `loadWalkGrid()`: returns `null` when `typeof location !== 'undefined'` and `new URLSearchParams(location.search).get('walkbake') === '0'`, or when the file has no tiles; otherwise `WalkGrid.fromJSON(bake as WalkFile)`; on any exception `console.error` and return `null`. Never throws.
- `scripts/bake-walk.mjs` (new): bundle with esbuild (stdin: `export * from './src/bakeWalk.ts'; export * from './src/terrainCore.ts'; export { ZONES, OBJECTS } from './src/content.ts'; export { loadWorldDeltas } from './src/worldDeltas.ts';`, `bundle`, `platform: 'node'`, `format: 'esm'`, temp dir from `mkdtempSync`, removed at the end, `external: ['three', '@lawn/gnome']` like the linter), import the bundle, then: `const t = createTerrain({ zones: ZONES, objects: OBJECTS, checkCondition: () => true })`, `const d = loadWorldDeltas(); if (d) t.setDeltas(d)`, `const grid = bakeWalkTiles(t, walkTileSpecs(ZONES))`, `grid.inputHash = computeBakeHash(t, ZONES)`, write `src/data/levels/walk.bake.json` as `JSON.stringify(grid.toJSON(), null, 1) + '\n'`. Print per-tile millis and the file size. Exit 0.
- `scripts/check-bake.mjs` (new): same bundle and terrain; read `src/data/levels/walk.bake.json` from disk; fail (print `walk bake is stale: run "npm run bake-walk -w games/gnomes-of-gnomomia" and commit the result`, exit 1) when its `inputHash` differs from `computeBakeHash(t, ZONES)` or its tile ids differ from `walkTileSpecs(ZONES)` ids; otherwise print `walk bake is up to date` and exit 0.
- `package.json` (CRLF!): scripts `"bake-walk": "node scripts/bake-walk.mjs"`, `"check-bake": "node scripts/check-bake.mjs"`, and change `"build"` to `"tsc --noEmit && node scripts/check-bake.mjs && vite build"`.
- Bootstrap: `walkBake.ts` imports the JSON, so the file must exist before anything compiles. First create `src/data/levels/walk.bake.json` as `{ "format": "lawn-walk", "version": 1, "cell": 0.25, "inputHash": "", "tiles": [] }`, then (after the scripts exist) run `npm run bake-walk -w games/gnomes-of-gnomomia` once (about 10 s) so the real file is committed-ready. Leave the generated file in place.
- `src/walkBake.test.ts` (new), using a fresh analytic terrain (`createTerrain({ zones: ZONES, objects: OBJECTS, checkCondition })`, imports like `terrainCore.test.ts`): (1) `BAKED_WALK_HASH === computeBakeHash(fresh, ZONES)`; (2) `walkTileSpecs(ZONES)` ids equal the baked file's tile ids; (3) for 20000 random cell centres (random tile, random cell, `mulberry32(7)`) `grid.solidAt(x, z) === fresh.staticSolidAt(x, z)`; (4) `loadWalkGrid()` returns a grid with 7 tiles; (5) the game's own `terrain` (import `{ terrain } from './terrain'`) has `terrain.walkGrid !== null`; (6) `computeBakeHash` changes when a stamp is added to a zone (copy `ZONES`, give `mossbottom` one `gauss` stamp, build a second terrain) and when `t.deltas.setUnits(0, 0, 50)` is called, and is identical for two fresh terrains.

## Contract
```ts
export interface WalkTileSpec { id: string; rect: Rect }
export function walkTileSpecs(zones: Record<ZoneId, ZoneDef>): WalkTileSpec[];
export function bakeWalkTiles(t: Terrain, specs: WalkTileSpec[], into?: WalkGrid): WalkGrid;
export function computeBakeHash(t: Terrain, zones: Record<ZoneId, ZoneDef>): string;
export const BAKED_WALK_HASH: string;
export function loadWalkGrid(): WalkGrid | null;   // never throws
```
