## Goal
`computeReachability` answers "can a walker get from this zone's spawn to everything that matters in it?" with a flood fill, so the editor (and a test) can flag a region, exit, house door or deck that a lake, a hill, a wall or a brush stroke has cut off.

## Change
- `src/reach.ts`: implement `computeReachability(t, def)`.
  - Grid: cell size 0.5 m over the square `origin +- (def.half + WORLD.blend)` (`origin = def.origin ?? {x:0,z:0}`), cell `(i, j)` centre at `(minX + (i + 0.5) * 0.5, minZ + (j + 0.5) * 0.5)`. A `Uint8Array` for visited, a typed-array queue (no per-cell objects: the grid can be 700 x 700).
  - Start: `t.findFreeSpot(def.spawn.x, def.spawn.z)` (spawn is already in world coordinates). 4-connected flood over cells where `!t.isBlocked(cx, cz)`.
  - `cells` = number visited. `reached(x, z)` = the cell containing `(x, z)` was visited (false outside the grid).
  - Targets (all world coordinates): `spawn` (the spawn), `shrine` (`def.shrine`), one `region` per region (its centre), one `exit` per exit that is NOT a door (`!e.door`), one `house` per house at its DOOR spot (the point just outside the door, using the dressing maths), one `deck` per deck at the foot of its ramp: `stair 's'` -> `(d.x, d.z + d.d/2 + 2*d.y)`, `'n'` -> `(d.x, d.z - d.d/2 - 2*d.y)`, `'e'` -> `(d.x + d.w/2 + 2*d.y, d.z)`, `'w'` -> `(d.x - d.w/2 - 2*d.y, d.z)`. `id`: the region/house/exit-`to`/deck index as a string (`'h3'`, `'deck0'`...; houses use `h.id ?? 'h' + index`); `label`: a readable name (region name, `'House h3'`, `'Exit to thatchford'`, ...).
  - A target is `reachable` when any visited cell has its centre within 1.5 m of the target (check the cells around it; targets may sit inside a collider's edge).
  - Use whatever gate state `t` has (the caller decides).
- `src/reach.test.ts` (new): build a fresh terrain with `checkCondition: () => true`; for `mossbottom`: `spawn`, `shrine` and every `region` are reachable and `cells > 10000`; a synthetic wall of lake: copy `ZONES`, give `mossbottom` a ring of lakes (e.g. 12 lakes of radius 12 on a circle of radius 30 around its spawn, overlapping) and check the spawn's own region still reaches the spawn but a region outside the ring is reported unreachable; and finally, for EVERY outdoor zone, run it and compare the list of unreachable targets (`zone:kind:id`) with a constant `KNOWN_UNREACHABLE: string[]` at the top of the test (sorted). Run it once, put whatever real unreachable targets exist today into that constant with a comment saying the content may need fixing (an empty array is the best outcome), and make the test fail when the list changes. Report that list in your final answer.

## Contract
(unchanged from the stub)
```ts
export interface ReachTarget { kind: 'spawn'|'shrine'|'region'|'exit'|'house'|'deck'|'prop'; id: string; label: string; x: number; z: number }
export interface ReachResult extends ReachTarget { reachable: boolean }
export interface ReachReport { zone: ZoneId; cells: number; results: ReachResult[]; reached(x: number, z: number): boolean }
export function computeReachability(t: Terrain, def: ZoneDef): ReachReport;
```
