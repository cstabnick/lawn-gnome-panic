Epic: 2 (integration). Depends on: none.

## Environment
Read `docs/roadmaps/level-format/_common.md` first and follow it. This is a browser tool: you cannot run it (no dev server, no WebGL in tests), so keep WebGL-free logic in a pure, tested module.

## Goal
The 3D view of the level editor: renderer, camera with orbit controls, the terrain meshed in chunks from the game's own `terrain`, ground picking, and re-meshing after edits.

## Read first
- `tools/level-editor/src/context.ts`: the `Viewport` interface you implement, exactly (every member).
- `tools/level-editor/src/viewport.ts`: the stub (keep `ViewportDeps` and `createViewport(container, deps): Viewport`).
- `tools/level-editor/src/main.ts`: how it is created and used (`setLeftOrbit`, `focus`, `refresh`).
- `games/gnomes-of-gnomomia/src/terrainCore.ts`: `Terrain.heightAt`, `groundColourAt`, `invalidate`.
- `games/gnomes-of-gnomomia/src/world.ts`: how the game meshes terrain chunks (`WORLD.chunk` = 64 m, vertex colours from `groundColourAt`); you do the simple version of this, you do not import `world.ts` (it needs the game's settings and state).
- `games/gnomes-of-gnomomia/src/config.ts`: `WORLD`, `TUNING.waterLevel`.

## Change
- `tools/level-editor/src/march.ts` (new, pure, no three.js): `export function marchToTerrain(ox, oy, oz, dx, dy, dz, heightAt, maxDist, step = 1): { x: number; y: number; z: number } | null`. Walk along the ray (direction need not be unit length: normalise it) in `step` metre steps from the origin; the first sample whose `y` is below `heightAt(x, z)` ends the march; refine between the previous and the current sample with 12 bisection steps; return the refined point with `y = heightAt(x, z)`. Return `null` when `maxDist` is reached, or when the origin itself is already below the ground.
- `tools/level-editor/src/march.test.ts` (new): flat ground at 0 (ray down-forward from (0,10,0) hits at the right x), a sloped ground `heightAt = x * 0.5` hit within 0.01 m of the analytic answer, a ray pointing up returns `null`, origin underground returns `null`, a hill between origin and target is hit before the far ground.
- `tools/level-editor/src/viewport.ts`: implement.
  - `THREE.WebGLRenderer({ antialias: true })` filling `container` (canvas `style.width/height 100%`), `setPixelRatio(Math.min(devicePixelRatio, 2))`; resize with `ResizeObserver` on `container` (update renderer size, camera aspect). `scene.background = new THREE.Color(0x9fd0f0)`, a `HemisphereLight(0xffffff, 0x446644, 1.1)` and a `DirectionalLight(0xfff2d6, 1.8)` at (200, 400, 150) with no shadows.
  - `PerspectiveCamera(50, aspect, 0.5, 4000)`. Controls: `import { OrbitControls } from 'three/examples/jsm/controls/OrbitControls.js'`, `enableDamping = false`, `maxPolarAngle = Math.PI * 0.49`, `minDistance = 5`, `maxDistance = 1500`. `setLeftOrbit(true)`: `mouseButtons = { LEFT: MOUSE.ROTATE, MIDDLE: MOUSE.PAN, RIGHT: MOUSE.PAN }`. `setLeftOrbit(false)`: `{ LEFT: null, MIDDLE: MOUSE.PAN, RIGHT: MOUSE.ROTATE }` (if the typings reject `null`, cast: `null as unknown as MOUSE`). Also `controls.listenToKeyEvents` is NOT used. The wheel zooms (default).
  - `focus(x, z, distance?)`: `controls.target.set(x, terrain.heightAt(x, z), z)`; with `distance` set the camera at `target + (0, 0.62 * distance, 0.78 * distance)`; without it keep the current offset direction and length. Call `controls.update()`.
  - Terrain meshes: chunk size `WORLD.chunk`, grid step 2 m (33 x 33 vertices per chunk, sharing nothing between chunks: each chunk samples its own border, so neighbours match exactly because `heightAt` is the same function). Mesh every chunk that overlaps any OUTDOOR zone rect grown by `WORLD.blend` (zones: `deps.zones`, `!z.indoor`, `origin ?? {0,0}`, `half`). Vertex colours from `terrain.groundColourAt(x, z)` (convert the 0xRRGGBB number to linear-ish r,g,b floats with `THREE.Color.setHex`), normals from `computeVertexNormals()`; `MeshLambertMaterial({ vertexColors: true })`. A flat translucent water plane (`MeshBasicMaterial({ color: 0x3a7bd5, transparent: true, opacity: 0.55, depthWrite: false })`) at `y = TUNING.waterLevel` large enough to cover all chunks. Keep the chunk meshes in a `Map<string, THREE.Mesh>` keyed `ci,cj`; build them in slices of at most 12 chunks per animation frame at start-up so the page stays responsive.
  - `refresh(rect?)`: rebuild only the chunks overlapping `rect` (all when omitted), disposing the old geometry. Rebuild synchronously (edits are small). Rebuild the chunk when it overlaps the rect grown by 2 m.
  - `pick(ev)`: normalised device coordinates from `ev.clientX/Y` and the canvas bounding rect; `new THREE.Raycaster().setFromCamera(ndc, camera)`; then `marchToTerrain(ray.origin..., ray.direction..., terrain.heightAt, 3000, 1)`; return `{x, y, z}` or `null`.
  - `overlay`: a `THREE.Group` added to the scene. `onFrame(fn)` registers a callback run every frame before `renderer.render`; returns the unsubscribe. The loop uses `requestAnimationFrame` with `dt` clamped to 0.1 s. `dispose()` stops the loop, removes listeners, disposes geometries/materials and the renderer.
  - Expose nothing global.
