Epic: 2 (integration). Depends on: none.

## Environment
Read `docs/roadmaps/level-format/_common.md` first and follow it. Browser tool: no dev server, no WebGL in tests; keep geometry maths pure and tested.

## Goal
The editor draws the active zone's layers on top of the terrain: its border, houses, lakes, regions, decks, props, stamps, roads, walls, spawn, shrine and exits, with the selected item highlighted. Drawing only: picking and editing belong to other tools.

## Read first
- `tools/level-editor/src/context.ts`: `EditorContext` (events `changed`, `selection`, `zone`; `zones`, `zone`, `terrain`, `viewport.overlay`, `selection`), `CollectionDef`, `Item`.
- `tools/level-editor/src/profile.ts`: `COLLECTIONS` (id, label, color, shape, radius, items, accepts) and `collection(id)`.
- `tools/level-editor/src/entityView.ts`: the stub (keep `createEntityView(ctx): { dispose(): void }`).
- `games/gnomes-of-gnomomia/src/config.ts`: `ZoneDef` (`spawn`, `shrine`, `exits`, `walls`, `paths`, `half`, `origin`), `PathDef` from `@lawn/level`.

## Change
- `tools/level-editor/src/overlayGeom.ts` (new, pure, no three.js): 
  - `ringPoints(cx, cz, r, heightAt, segments = 48, lift = 0.4): [number, number, number][]` (closed loop of `segments + 1` points, y = `heightAt(x, z) + lift`, last point equals the first);
  - `rectPoints(cx, cz, w, d, heightAt, stepM = 2, lift = 0.4): [number, number, number][]` (the outline of the axis-aligned box, points at most `stepM` apart along each side so it follows the ground, closed);
  - `polylinePoints(points: [number, number][], heightAt, stepM = 2, lift = 0.4): [number, number, number][]` (subdivides each segment so no two points are more than `stepM` apart);
  - `zoneBorderRect(def: { origin?: {x:number;z:number}; half: number }): { cx: number; cz: number; w: number; d: number }`.
- `tools/level-editor/src/overlayGeom.test.ts` (new): closed loops, point counts, y follows a sloped `heightAt`, spacing never exceeds `stepM`, border of a zone with an origin.
- `tools/level-editor/src/entityView.ts`: implement `createEntityView(ctx)`.
  - Own one `THREE.Group` (`name = 'entity-view'`) inside `ctx.viewport.overlay`; rebuild its children (dispose the old geometries) whenever `ctx.events.changed`, `ctx.events.selection` or `ctx.events.zone` fires, coalesced to at most once per animation frame.
  - For the active zone (`ctx.zones[ctx.zone]`) draw, as `THREE.Line` / `LineLoop` with `LineBasicMaterial` (`depthTest: false`, `renderOrder: 10` so it is always visible): the zone border (white, 0.5 opacity); every item of every `COLLECTIONS` entry (`items(def)` filtered by `accepts`): circle shapes as `ringPoints` of `radius(item)`, rect shapes as `rectPoints(item.x, item.z, item.w, item.d)`, plus a vertical line 6 m tall at the centre, in the collection's `color`; authored roads (`def.paths` kind `'road'`: brown `0xb5834a`, `polylinePoints`), walls (`def.walls`, grey), the game's derived roads (`ctx.terrain.roadSegments()` clipped to the active zone's border rectangle, thin, dark yellow `0x8a7a3a`), spawn (cyan ring r 1), shrine (magenta ring r 1.2), exits (green ring of their `r`).
  - The selected item (`ctx.selection`: `{ collection, index }` with `index` into `collection.items(def)`) is drawn a second time in white with a ring 0.6 m larger, so it stands out.
  - Note `items(def)` may create the array (`def.props ??= []`): that is fine, it is empty.
  - Return `{ dispose() }` that unsubscribes everything and removes the group.
