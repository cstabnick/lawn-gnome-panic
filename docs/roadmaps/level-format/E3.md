## Environment
Read `docs/roadmaps/level-format/_common.md` first and follow it. Browser tool: no dev server; keep the stroke maths pure and tested. `applyBrush` (in `@lawn/level`) is being implemented by another worker at the same time: it is a stub that returns an empty patch until then; code against its signature.

## Goal
The Brush tool: paint terrain up, down, smoother or flat with the mouse, with live preview and one undo step per stroke.

## Read first
- `tools/level-editor/src/context.ts`: `Tool`, `EditorContext` (`viewport.pick/dom/overlay/setLeftOrbit`, `terrain`, `deltas`, `touch`, `commitDeltas`, `status`), `GroundHit`.

- `packages/level/src/brush.ts`: `applyBrush(grid, op, heightAt): DeltaPatch`, `BrushOp`, `BrushMode`. `packages/level/src/deltas.ts`: `PatchBuilder` (`add`, `build`, `bounds`), `DeltaPatch`.
- `tools/level-editor/src/tools/view.ts`: a finished tool, for the shape.

## Change
- `tools/level-editor/src/tools/strokeMath.ts` (new, pure): `export function dabPositions(from: {x:number;z:number} | null, to: {x:number;z:number}, spacing: number, carry: number): { points: {x:number;z:number}[]; carry: number }` places dab centres every `spacing` metres along the segment `from -> to` (when `from` is `null` it returns exactly one point at `to`), continuing the distance already walked (`carry`, metres since the last dab) so dabs are evenly spaced across many small mouse moves; returns the new `carry`.
- `tools/level-editor/src/tools/strokeMath.test.ts` (new): one point for the first dab; spacing exact on a long move; carry continues across two short moves; zero-length move returns no points.
- `tools/level-editor/src/tools/brush.ts`: implement the tool.
  - Panel (built in `mount`): four mode buttons (Raise, Lower, Smooth, Flatten; the active one has class `on`), a Radius slider (1-40 m, default 8), a Strength slider (raise/lower: 0.05-1.0 m per dab, default 0.25; smooth/flatten: 0.05-1.0 fraction, default 0.4; keep one stored value per mode), a Flatten height number input (metres, default 0) with a "Pick" button (next click on the terrain, in any mode, copies the ground height there into the field and the button turns off), and a hint line: `Left-drag paints. Shift inverts raise/lower. [ and ] change the radius. Alt-click sets the flatten height.`
  - `activate()`: add on `ctx.viewport.dom`: `pointerdown` (button 0 only), `pointermove`, and on `window` `pointerup`/`pointercancel`, and `keydown` for `[` `]`. Create a cursor ring (`THREE.LineLoop`, 48 points, `depthTest: false`, `renderOrder 11`, colour by mode) in `ctx.viewport.overlay` that follows the hover point (`viewport.pick(ev)`) at `y = hit.y + 0.3` and has the brush radius (rebuild the geometry when the radius changes).
  - A stroke: on `pointerdown`, `setPointerCapture`, create a `PatchBuilder`, place the first dab (`dabPositions(null, hit, ...)`), then on each `pointermove` while down place the dabs `dabPositions(last, hit, Math.max(0.5, radius * 0.25), carry)` returns. Each dab: `const patch = applyBrush(ctx.deltas, op, ctx.terrain.heightAt)` with `op = { mode, x, z, radius, strength, target }` (Shift while pressing/dragging swaps raise <-> lower; flatten `target` is the Flatten height field), then `builder.add(patch)` and `ctx.touch(dabRect)` where `dabRect = { minX: x - radius - 2, maxX: x + radius + 2, minZ: z - radius - 2, maxZ: z + radius + 2 }`. Because `touch` invalidates the terrain, the next dab's `heightAt` sees the new heights.
  - On `pointerup`: `ctx.commitDeltas(`Brush ${mode}`, builder.build(), builder.bounds() ?? dabRect, true)` (the patch is already applied, `applied = true`); do nothing if the built patch is empty.
  - Alt-click (button 0 with `altKey`) does not paint: it only sets the Flatten height field from `hit.y`. The "Pick" button arms the same behaviour for the next click.
  - `deactivate()`: remove every listener and the cursor ring (dispose its geometry); if a stroke is in progress, commit it first.
  - Show `ctx.status(...)` messages: the mode and radius when it changes, and `Painted N vertices` after a stroke.
