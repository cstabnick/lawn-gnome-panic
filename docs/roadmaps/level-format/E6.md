## Environment
Read `docs/roadmaps/level-format/_common.md` first and follow it. Browser tool: no dev server; keep the pixel-painting maths pure and tested. Three game modules you import are stubs right now and other workers are filling them in: `@gnomomia/reach` (`computeReachability`), `@gnomomia/bakeWalk` (`walkTileSpecs`, `bakeWalkTiles`, `computeBakeHash`) and `@gnomomia/walkBake` (`loadWalkGrid`); `saveWalk` in `persist.ts` is also a stub. Code against their signatures only.

## Goal
The Analyze tool: show where a walker cannot go, test a path between two clicks, report whether the zone's spawn can reach everything that matters, and re-bake the walkability grid after edits.

## Change
- `tools/level-editor/src/tools/overlayPaint.ts` (new, pure): `export function paintGrid(rect: Rect, cell: number, cellColour: (x: number, z: number) => [number, number, number, number]): { width: number; height: number; data: Uint8ClampedArray }` returns RGBA pixels, one per `cell` metres (pixel `(i, j)` samples the cell centre `(rect.minX + (i + 0.5) * cell, rect.minZ + (j + 0.5) * cell)`; row 0 is `minZ`).
- `tools/level-editor/src/tools/overlayPaint.test.ts` (new): size from rect and cell, a checker function lands in the right pixels, an all-transparent function gives all zeros.
- `tools/level-editor/src/tools/analyze.ts`: implement.
  - Panel sections (each an `<h3>` + controls):
    1. **Walkability**: a checkbox "Show blocked ground". When on, build one overlay mesh for the ACTIVE zone: rect = `zoneRect(def)`; a `THREE.PlaneGeometry(w, d, w / 2, d / 2)` rotated flat whose vertices are lifted to `terrain.heightAt(x, z) + 0.25` (do it like the game's terrain: set each vertex from its world x/z), textured with a `THREE.DataTexture` (or `CanvasTexture`) from `paintGrid(rect, 0.5, ...)` where a blocked cell (`terrain.isBlocked(x, z)`) is `[230, 40, 40, 140]`, and (when a reachability report exists) a free cell that the flood fill did NOT reach is `[255, 170, 0, 110]`; free reached cells transparent. `MeshBasicMaterial({ map, transparent: true, depthWrite: false, polygonOffset: true, polygonOffsetFactor: -2, side: THREE.DoubleSide })`. Mind texture orientation: texture row 0 must land on the plane's `minZ` edge. Rebuild (debounced 250 ms) on `ctx.events.changed` and `zone` while shown. Remove and dispose when unchecked or the tool deactivates.
    2. **Path test**: a button "Test path" (toggle, class `on`). While on, the first terrain click sets A (green sphere r 0.8) and the second B (red sphere); then `findPath3({ x: A.x, y: A.y, z: A.z }, { x: B.x, y: B.y, z: B.z }, ctx.terrain.standY, 60000)` and draw the waypoints as an orange `THREE.Line` (+0.5 m above the ground, `depthTest: false`, `renderOrder 12`) from A through the waypoints. Report in a text line: number of waypoints, total length in metres, and `reached` / `stopped short by N m` (the last waypoint's distance to B within 1.5 m = reached; an empty path = `no path`). The next click starts a new pair.
    3. **Reachability**: a button "Run reachability". It runs `computeReachability(ctx.terrain, ctx.zones[ctx.zone])`, shows `cells visited` and a list of every result (`✓` or `✗` + `label`; unreachable first). Clicking a row calls `ctx.viewport.focus(x, z, 60)`. Unreachable targets get a red vertical pole (4 m, `depthTest: false`) in the overlay. A line says whether gates are open (`ctx.gatesOpen`): "Gates open: reachability ignores quest gates" / "Gates closed: as in a new game". Running it again, switching zone or any `changed` event marks the old report stale (grey the list, text `out of date: run again`) rather than recomputing automatically (it takes a moment).
    4. **Walk bake**: text `N edited area(s) need a re-bake` (from `ctx.dirty.walkRects.length`; `Up to date` when 0) and a button "Re-bake walkability and save". On click: `ctx.status('Baking...')`, wait one animation frame so the status paints, then `const base = loadWalkGrid() ?? new WalkGrid()`; `const specs = walkTileSpecs(ctx.zones)`; keep only the specs whose rect overlaps any rect in `ctx.dirty.walkRects` (all specs when `base` has no tiles); `bakeWalkTiles(ctx.terrain, specs, base)`; `base.inputHash = computeBakeHash(ctx.terrain, ctx.zones)`; `await saveWalk(base.toJSON())`; then empty `ctx.dirty.walkRects` and report `Baked N tile(s) in X s, saved <file>`. On error show it in `ctx.status` and keep `dirty.walkRects`. NOTE: the editor's terrain has no walk grid installed, so `staticSolidAt` is always the live computation: that is what must be baked. Because the shipped bake of an UNEDITED tile is still valid, only dirty tiles are re-baked.
  - `activate()`/`deactivate()`: attach/remove the click listener on `ctx.viewport.dom` for the path test (button 0, ignore when it was a drag: compare pointerdown and pointerup positions within 4 px), and remove every overlay object you added.
