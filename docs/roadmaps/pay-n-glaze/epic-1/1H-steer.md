## Environment
Read `docs/roadmaps/pay-n-glaze/_common.md` first (working directory, toolchain, rules, how to report). You own only the files below.

## Goal
Steering: (1) a game-private variant of a prefab whose steering wheel is moved within a seated gnome's reach, without touching the shared catalogue prefab; (2) steering-wheel styles; (3) the two grip markers the gnome's hands will follow, which turn with the wheel.

## Read first

- `packages/glaze/src/steer.ts`: the stub (`steerVariantId`, `registerSteerVariant`, `resolveBodyPrefab`, `applySteer`: keep the signatures).
- `packages/prefabs/src/registry.ts`: `registerPrefab(def)` (new: adds a def at run time; throws on a duplicate id), `getPrefab(id)`. `packages/prefabs/src/types.ts`: `PrefabDef`, `Part`.
- `packages/prefabs/src/catalog/lawn-prix.ts` lines 10-40: `ride-on-mower` (pivot `steer` at `[0, 1.1388, 0.0103]`, its ring part `{ s: 'ring', rot: [90, 0, 0], at: [0, 1.1388, 0.0103], group: 'steer' }` is a horizontal wheel, and the column is the static `cyl` part at parts index 6).
- `packages/prefabs/src/build.ts` lines 226-290: how a pivot group is built (group position = pivot `at`; a part's local position = `at - pivot at`) and `buildPrefab`/`setPrefabDamage` (rebuild from the REGISTRY by `root.userData.prefab`, which is why a variant must be registered).
- `docs/roadmaps/pay-n-glaze/_prefabs.md`, the **Steering wheels** rule (the prefabs `glaze-steer-<id>` another worker writes: flat in x-z, on y = 0, 12 o'clock +z, rim at the grip radius). Until they exist `getPrefab` returns `undefined`: keep the stock wheel then.

Compute `rot` in DEGREES for the `XYZ` Euler convention used by prefab parts (a rotation about z then x is enough for a column that is mostly vertical: `rx = atan2(dz, dy)`, `rz = -atan2(dx, hypot(dy, dz))` in degrees; check it by building the variant and verifying with a `Box3` in the test that the column's top end reaches `wheelAt` within 0.03).
